1. Noice                                                    *noice.nvim-noice*

A stripped-down fork of folke/noice.nvim built around three UI features:

- a floating cmdline with per-command icons, titles and Treesitter highlighting
- search count as virtual text next to the matching line (`/`, `?`, `n`, `N`)
- LSP progress as a small notification in the bottom-right corner

LSP hover, signature help, the `vim.notify` replacement, the markdown renderer,
the popupmenu (wildmenu) UI and the desktop-notification backends have been
removed. What remains besides those three features is the
plumbing they force (see below) plus the `:Noice` commands, the message history
with its pickers, the statusline API and the confirm dialog.

MESSAGES                                           *noice.nvim-noice-messages*

Neovim only emits the `msg_show` event with kind `search_count` when a UI
attaches with `ext_messages`. That flag makes Neovim hand every message to the
plugin, so the search count virtual text is not available without also taking
over messages. Returning from the handler does not hand a message back to
Neovim to draw — it only stops propagation to remote UIs.

`ext_messages` also implies `ext_cmdline` and sets `cmdheight=0`. So
`messages.enabled = false` disables the search count, and
`cmdline.enabled = false` while messages are on leaves nothing drawing the
cmdline at all.

All non-search messages are forwarded to the `notify` view, which renders
through snacks.nvim and falls back to the built-in `mini` view. Set
`messages.view`, `messages.view_error`, `messages.view_warn` and
`messages.view_history` to change that. `messages.view_search` controls the
search count view and defaults to `virtualtext`.

REQUIREMENTS                                   *noice.nvim-noice-requirements*

- Neovim >= 0.9.0 (0.11+ recommended, 0.10+ for LSP progress)
- nui.nvim
- snacks.nvim for the `notify` view (optional, falls back to `mini`)
- a Nerd Font for the cmdline icons (optional)
- `vim.opt.termguicolors` enabled
- the `vim`, `regex`, `lua` and `bash` Treesitter parsers

INSTALLATION                                   *noice.nvim-noice-installation*

>lua
    -- lazy.nvim
    {
      "NorinB/noice.nvim",
      event = "VeryLazy",
      opts = {},
      dependencies = { "MunifTanjim/nui.nvim" },
    }
<

Run `:checkhealth noice` after installing.

CONFIGURATION                                 *noice.nvim-noice-configuration*

See the README for the full default configuration. The top level options are:

  `cmdline`   enable the cmdline UI, pick its view and the per-command formats
  `messages`  enable the messages UI, pick the views for each message type and
              cap the history with `history_max`
  `lsp`       `progress.enabled`, `progress.view` and `progress.throttle` for
              the LSP progress notification
  `commands`  custom `:Noice <name>` commands
  `health`    periodic health checks
  `presets`   `bottom_search`, `command_palette`, `inc_rename`
  `throttle`  how often Noice checks for UI updates
  `views`     view overrides
  `routes`    custom routes
  `status`    statusline components
  `format`    formatting options
  `debug`     enable debug mode
  `log`       path of the Noice log file

FILTERS                                             *noice.nvim-noice-filters*

Filters select the messages a route applies to. Every field must match, unless
it is nested under `any` or `not`.

  `cleared`                   message was cleared
  `mode`                      `vim.api.nvim_get_mode().mode` matches
  `blocking`                  Neovim is waiting for input
  `event`                     ui event, e.g. `msg_show` or `cmdline`
  `kind`                      ui event kind, e.g. `search_count`
  `error` / `warning`         message level
  `find`                      Lua pattern matched against the content
  `message`                   message is one of these messages
  `cond`                      custom predicate
  `min_height` / `max_height` height of the message
  `min_width` / `max_width`   width of the message
  `min_length` / `max_length` length of the message content
  `cmdline`                   Lua pattern matched against the active cmdline
  `any`                       at least one of the nested filters matches
  `not`                       the nested filter does not match
  `has`                       the message is still active

VIEWS                                                 *noice.nvim-noice-views*

A view is a backend plus a set of options. Backends: `popup`, `split`, `mini`,
`snacks` and `virtualtext`.

Configured views: `virtualtext`, `notify`, `split`, `messages`, `lsp_progress`,
`popup`, `cmdline`, `mini`, `cmdline_popup`, `cmdline_input` and `confirm`.

The `lsp_progress` view is the `mini` backend in the bottom-right corner. Move
it to the bottom-left with:

>lua
    require("noice").setup({
      views = { lsp_progress = { position = { col = 0 }, align = "message-left" } },
    })
<

`lsp_progress` and `mini` are separate windows in the same corner. Without
snacks.nvim the `notify` view falls back to `mini` and the two overlap; let
them share one window instead, which stacks the lines (and uses `mini`'s
2000 ms timeout):

>lua
    require("noice").setup({
      lsp = { progress = { view = "mini" } },
    })
<

LSP progress needs Neovim 0.10+ for the `LspProgress` event and is skipped on
older versions.

Override or add views with the `views` option:

>lua
    require("noice").setup({
      views = {
        cmdline_popup = {
          position = { row = 5, col = "50%" },
          size = { width = 60, height = "auto" },
        },
      },
    })
<

FORMATTING                                       *noice.nvim-noice-formatting*

A format is a list of format elements: `{message}`, `{title}`, `{level}`,
`{event}`, `{kind}`, `{date}`, `{cmdline}`, `{data}`, `{text}`, `{confirm}` and
`{debug}`.

Built-in formats: `default`, `notify`, `details`, `telescope`,
`telescope_preview`, `fzf`, `fzf_preview`, `snacks` and `snacks_preview`.

ROUTES                                               *noice.nvim-noice-routes*

A route is `{ view, filter, opts }`. Custom routes are prepended to the
defaults, so they win.

>lua
    require("noice").setup({
      routes = {
        { filter = { event = "msg_show", find = "written" }, opts = { skip = true } },
      },
    })
<

Route options: `skip` drops the message, `stop` (default `true`) stops
processing further routes. Any other option is passed to the view.

STATUSLINE COMPONENTS                 *noice.nvim-noice-statusline-components*

>lua
    require("noice").api.status.mode.get()
    require("noice").api.status.mode.has()
<

Available components: `message`, `command`, `mode`, `search` and `ruler`.

PICKERS                                             *noice.nvim-noice-pickers*

Message history can be browsed with `snacks.picker`, `telescope.nvim` or
`fzf-lua`: `:Noice pick`, `:Noice snacks`, `:Noice telescope`, `:Noice fzf`.

USAGE                                                 *noice.nvim-noice-usage*

  `:Noice` or `:Noice history`         show the message history
  `:Noice last`                        show the last message
  `:Noice dismiss`                     dismiss all visible messages
  `:Noice errors`                      show the error history
  `:Noice disable` / `:Noice enable`   stop or start Noice
  `:Noice all`                         show all messages, internal included
  `:Noice stats`                       show debugging stats
  `:Noice routes`                      dump the resolved routes
  `:Noice config`                      dump the resolved config
  `:Noice viewstats`                   dump per-view message counts
  `:Noice debug`                       toggle debug mode
  `:Noice log`                         open the Noice log file

Every command is also available as `:Noice<Name>`, e.g. `:NoiceDismiss`.
